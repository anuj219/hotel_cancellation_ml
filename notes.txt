Hyperparamter tuning - 
    paramter-   
        model learns from data
        eg weights in Logistic reg, decision thresholds, leaf predictions
        not set manually    
    Hyperparamter - 
        they control how the model learns
        eg nestimators, max_depth etc
        chosen before training
        it is to find the sweet spot [no under/over fitting]
        
        n_estimators - more stability but moren train time
        max_depth - deepness, controls overfitting
        min_samples_split - min samples needed to split a node, prevents tiny splits
        min_samples_leaf - min samples for a leaf, prevents tiny overfit leaves
        max_features - num of features considered at each split

    methods to find best params-
        grid search - 
            you provide a list/range for each parameter,
            so each permutation combination makes a model and tests it
            can become slow
        randomized search - 
            samples combinations randomly
            commonly preferred for large search spaces

            RandomizedSearchCV - repeatedly trains RF with diff Hyperparamters

    implementation-
        search = RandomizedSearchCV(
            estimator=pipeline,   # means tuning entire pipeline
            param_distributions=param_dist,
            n_iter=10, # try random 20 possible combinations, of parameters
            scoring="f1", #
            cv=5,  # 5-fold cross-validation, training data split into 5 parts, trains 5 times
            # 4 fold -> training, 1 fold -> validation, then avg f1-score
            verbose=2, # prints progress
            random_state=42, # someone else runs with same seed, they will get same 20 sample combinations
            n_jobs=1 # -1 means use all cpu cores, speeds it up | 1 means ??
        )
        output - 
            {'model__n_estimators': 200, --> The forest uses 200 decision trees.
            'model__min_samples_split': 2, --> node only needs 2 samples before it is allowed to split
            'model__min_samples_leaf': 1, --> Each leaf can contain just one sample, thus no evidence was found that larger leaves generalized better
            'model__max_features': 'log2', --> RF randomly chooses only log2(no. of features)
                                            So each split only considers about 5–6 random features (out of 50)
                                            If every tree always looked at every feature, all trees would become similar
                                            Randomness is what makes Random Forest powerful
            'model__max_depth': 30, --> very detailed rules
            }
            0.7550509494705987 --> Average F1 over the 5 validation folds

            The model with the best average cross-validation score doesn't always

ROC curve - ((Receiver Operating Characteristic))
    currently, RF uses 0.5 as threshold to classify cancelled or not_cancelled
    that is default
    maybe some other threshold might work better
    ROC helps study every possible threshold    

    threshold optimization-
        to find threshold that maximizes f1 score 
        [why focus on f1 though --- Since the dataset is moderately imbalanced (67% : 33%) and F1-score is a better metric than plain accuracy]
        so we take thresholds from 0.10 to 0.90 and use model to get probability of cancellations
        and then, test each threshold on probabilities and then calculate f1 score at each loops end
        then see which one has best score

        > best threshold found - 0.3999
        its score - 0.771
        improvement can be seen
        plotted all thresholds and their scores

    applied optimum and printed the classification report
    >> 
              precision    recall  f1-score   support

           0       0.88      0.84      0.86     22560
           1       0.75      0.80      0.77     13257

    accuracy                           0.82     35817
    macro avg       0.81      0.82      0.81     35817
    weighted avg       0.83      0.82      0.83     35817
    After threshold optimization, the model became better at identifying cancellations (inc from 0.72 to ~0.80), 
    at the expense of correctly identifying some non-cancelled bookings (class 0 recall decreased from ~0.91 to ~0.84). 
    This trade-off increased the overall F1-score while maintaining similar accuracy


SHAP - 
    RF cant answer by default, the reason or metrics behind a single predictions
    Feature importance is global, it tells which feature impacts how much overall
    but for explainability, we need more granular output
    SHAP does that
        it gives impact of each feature for that particular prediction
        pushing towards either of the classes
        This is kind of explainable AI
